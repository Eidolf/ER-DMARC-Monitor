Audit Methodology & Scope

This handbook provides an executable audit framework designed for test engineers, compliance auditors, and security teams. Every test scenario corresponds directly to requirements verified in the QA & Security Assessment and structural components documented in the arc42 Software Architecture.

All verification procedures can be executed from a standard administrative workstation or CI runner with Docker, Python 3, and curl installed.

Detailed Execution Procedures

TC-01

Direct Inbound SMTP Ingestion & Archive Extraction

Ingestion & Transport

Objective: Verify the SMTP receiver accepts compliant DMARC report emails with GZ/ZIP attachments and pushes raw payloads to Redis.

Prerequisites: Docker stack running; smtp-ingester listening on port 2525.

Executable Verification Command:
python3 scripts/smtp_tests/test_dmarc.py --host localhost --port 2525 --domain test.example.com --to dmarc@reports.example.com
Expected Output & Behavior:

250 Message accepted for delivery. Log output shows successful attachment decompression and redis.lpush('dmarc_queue', ...).

PASS CRITERIA Return code 0, queue increment verified, no attachment parsing errors in smtp-ingester container logs.
TC-02

SMTP Open Relay & Unauthorized Recipient Rejection

SMTP Security

Objective: Confirm the receiver strictly forbids outbound relaying or unauthorized recipient relay attempts.

Prerequisites: Configured allowed domains list in environment (ALLOWED_DOMAINS).

Executable Verification Command:
python3 -c "import smtplib; s=smtplib.SMTP('localhost', 2525); s.sendmail('attacker@evil.com', ['victim@external.org'], 'Subject: Test\r\n\r\nRelay probe'); s.quit()"
Expected Output & Behavior:

550 5.7.1 Relay access denied / Recipient address rejected: domain not hosted.

PASS CRITERIA SMTP connection terminated with 5xx error; mail dropped immediately without queueing.
TC-03

Malformed XML & XXE Injection Defense

Parser Hardening

Objective: Verify that malformed XML reports, entity expansion attacks (Billion Laughs), and XXE payloads are safely rejected without crashes or data leaks.

Prerequisites: dmarc-parser service operational.

Executable Verification Command:
docker exec -i er-dmarc-monitor-api python3 -c "from defusedxml.minidom import parseString; parseString('<?xml version=\"1.0\"?><!DOCTYPE lolz [<!ENTITY lol \"lol\"><!ELEMENT lolz (#PCDATA)>]><lolz>&lol;</lolz>')"
Expected Output & Behavior:

EntitiesForbidden or DfxmlException exception raised; parsing aborted safely.

PASS CRITERIA Parser does not execute entity lookups, container remains healthy with zero memory exhaustion.
TC-04

Asynchronous Redis Queue to PostgreSQL Pipeline

Data Flow & Consistency

Objective: Validate that queued records are dequeued, processed by dmarc-parser, and populated into PostgreSQL tables (report_metadata & report_record).

Prerequisites: PostgreSQL database initialized and reachable.

Executable Verification Command:
docker exec er-dmarc-monitor-db psql -U postgres -d dmarc -c "SELECT id, org_name, domain_name, date_begin FROM report_metadata ORDER BY id DESC LIMIT 1;"
Expected Output & Behavior:

Record returned matching the latest ingested test report ID with valid timestamp ranges.

PASS CRITERIA Database transaction committed without foreign key violations or data loss.
TC-05

Local Authentication, Salted Hashing & Timing Attack Resilience

Authentication

Objective: Audit password authentication, verifying bcrypt/argon2 hashing and rejection of invalid credentials.

Prerequisites: API running on port 8080.

Executable Verification Command:
curl -s -X POST http://localhost:8080/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"WrongPassword!"}'
Expected Output & Behavior:

HTTP 401 Unauthorized with {'detail': 'Invalid username or password'}.

PASS CRITERIA Authentication fails cleanly, event logged in LoginAudit table, no internal database errors exposed.
TC-06

MFA / TOTP Enforcement & Recovery Codes

Access Control

Objective: Ensure users with MFA enabled cannot generate valid session tokens without secondary TOTP challenge validation.

Prerequisites: Test user with mfa_enabled=True.

Executable Verification Command:
curl -s -X POST http://localhost:8080/api/auth/challenge-mfa -H 'Content-Type: application/json' -d '{"temp_token":"...", "totp_code":"000000"}'
Expected Output & Behavior:

HTTP 401 Invalid verification code.

PASS CRITERIA No JWT session token issued until valid 6-digit TOTP matching shared secret or backup code is submitted.
TC-07

RBAC Privilege Separation & Endpoint Guardrails

Authorization

Objective: Verify that Analyst users cannot mutate system settings, manage users, or modify domain configurations.

Prerequisites: Active Analyst JWT access token.

Executable Verification Command:
curl -s -X POST http://localhost:8080/api/admin/settings -H 'Authorization: Bearer <ANALYST_TOKEN>' -H 'Content-Type: application/json' -d '{"allow_local_login":true}'
Expected Output & Behavior:

HTTP 403 Forbidden with {'detail': 'Insufficient administrative privileges'}.

PASS CRITERIA Mutation blocked at FastAPI dependency layer before database handler execution.
TC-08

Audit Logging Completeness & Non-Repudiation

Audit & Compliance

Objective: Audit the login audit trail for tracking authentication events, IP addresses, and timestamps.

Prerequisites: At least one login attempt executed.

Executable Verification Command:
docker exec er-dmarc-monitor-db psql -U postgres -d dmarc -c "SELECT id, user_id, timestamp, ip_address, method, status FROM login_audit ORDER BY id DESC LIMIT 5;"
Expected Output & Behavior:

Audit records showing timestamp, client IP, method (LOCAL, MFA, SSO), and status (SUCCESS / FAILURE).

PASS CRITERIA Audit entries are immutable, timestamps correspond to UTC, and failed attempts capture origin IP.
TC-09

Static Secrets & Configuration Externalization Audit

Secure Coding

Objective: Verify that no production credentials, JWT signing keys, or cloud client secrets are hardcoded in the codebase.

Prerequisites: Local git repository clone.

Executable Verification Command:
grep -rnE "(secret_key|jwt_secret|entra_client_secret)[ \t]*=[ \t]*['\"][^'\"]+['\"]" api/ dmarc-parser/ smtp-ingester/ || echo 'AUDIT PASSED: No hardcoded secrets'
Expected Output & Behavior:

'AUDIT PASSED: No hardcoded secrets' (all retrieved via os.getenv / .env / Settings).

PASS CRITERIA Zero hardcoded keys identified in application source directories.
TC-10

Container Isolation & Non-Root Execution Check

Deployment & Isolation

Objective: Inspect running containers to verify process isolation, health checks, and unprivileged user execution where configured.

Prerequisites: Docker engine active.

Executable Verification Command:
docker compose ps --format 'table {{.Name}} {{.Status}} {{.Ports}}'
Expected Output & Behavior:

All core services (db, redis, api, dmarc-parser, smtp-ingester, frontend) in 'healthy' or 'Up' state.

PASS CRITERIA Only designated ports (8080, 2525, 5173/80) exposed to host; inter-service communication contained within Docker bridge network.
